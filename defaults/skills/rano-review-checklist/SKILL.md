# 검수 체크리스트 (rano-review-checklist)

검수는 "괜찮아 보인다"가 아니라 **항목마다 확인한 근거**를 남기는 일이다. 고치지 말고 판정과 고칠 점만 낸다.

## 점검 항목 (모두 본다)
1. **결과물 대조**: 과제가 요구한 결과물(종류·위치·개수·이름·형식)과 실제를 하나씩 맞춘다.
2. **사실 근거**: 문서의 주장·숫자마다 근거 파일·위치가 있는지. 근거를 직접 열어 맞는지 확인(최소 3곳 무작위).
3. **숫자 다시 계산**: 합계·비율·단위 변환을 직접 다시 계산해 본다. 엑셀이면 수식이 맞는 칸을 가리키는지.
4. **빠진 것**: 지시에 있었는데 빠진 항목, 빈 칸, "TODO", "확인 필요"가 남았는지.
5. **비밀·개인 정보**: 토큰·비밀번호·접속 주소·개인 연락처가 들어갔는지.
6. **쉬운 말**: 읽는 사람이 비개발자여도 이해할 수 있는지. 풀어 쓰지 않은 기술 용어.
7. **범위 지킴**: 맡긴 범위 밖 파일이 바뀌지 않았는지(작업 폴더 상태, 바뀐 파일 목록).
8. **파일 결과물**: 엑셀·워드·PPT·PDF 면 실제로 열리는지(문서 도구 파이썬으로 열어 시트·쪽·장 수 확인, 실행은 승인함).

## 결과 틀
```markdown
## 검수 결과: 통과 / 조건부 통과 / 보완 필요

| 항목 | 판정 | 근거 |
|---|---|---|
| 결과물 대조 | 맞음 / 다름 | <무엇과 무엇을 맞춰 봤는지> |
| 사실 근거 | | |
| 숫자 다시 계산 | | |
| 빠진 것 | | |
| 비밀·개인 정보 | | |
| 쉬운 말 | | |
| 범위 지킴 | | |
| 파일 결과물 | 해당 없음 / 열림 | |

## 고칠 점 (중요한 것부터)
1. <파일:위치> — <무엇이 왜 문제인지> → <어떻게 고치면 되는지>
```

## 지킬 것
- 확인하지 못한 항목은 "확인 못 함"과 이유를 적는다. 통과로 넘기지 않는다.
- 다시 검수할 때는 지난번 고칠 점이 하나씩 고쳐졌는지부터 본다.
