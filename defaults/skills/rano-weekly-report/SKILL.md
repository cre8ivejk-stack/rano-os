# 주간 보고 틀 (rano-weekly-report)

한 미션의 한 주(월~금)를 사람이 3분 안에 읽을 수 있게 정리한다. 사실만 쓰고, 근거 위치를 남긴다.

## 모을 곳 (읽기만)
1. 미션 홈의 `memory/진행업무.md`, `memory/결정로그.md` — 진행 중인 일, 이번 주 결정
2. 미션 홈의 `outputs.md` — 끝난 과제와 결과물 위치
3. 작업 폴더의 git 기록 — `git log --since="<월요일>" --until="<금요일 다음날>" --oneline` (읽기 명령)
4. 지시에 붙은 메모나 그림

기간을 지시에서 못 찾으면 "이번 주 월요일 ~ 오늘"로 하고, 보고 맨 위에 기간을 적는다.

## 틀 (이 순서와 제목 그대로)

```markdown
# <미션 이름> 주간 보고 (<YYYY-MM-DD> ~ <YYYY-MM-DD>)

## 한 줄 요약
<이번 주 가장 중요한 결과 한 문장>

## 한 일
| 일 | 결과 | 근거 |
|---|---|---|
| <과제·작업> | <완료 / 진행 중 n% / 멈춤> · <무엇이 달라졌는지> | <결과물·파일·커밋> |

## 결정된 것
- <날짜> <결정 내용> (누가, 왜)

## 결정이 필요한 것
- <질문> — 권장: <권장안> (마감이 있으면 날짜)

## 다음 주 할 일
1. <할 일> — <담당 역할>

## 위험·막힌 것
- <내용> → <대응>  (없으면 "없음")
```

## 지킬 것
- 숫자·날짜·파일 이름은 위 "모을 곳"에서 확인한 것만 쓴다. 모르는 것은 "확인 필요"로 남긴다.
- 기술 용어는 쉬운 말로 풀고, 한 칸은 한두 줄로 짧게 쓴다.
- 결과는 이 과제의 시안 폴더에 `주간보고_<YYYYMMDD>.md` 로 먼저 만든다. 워드·PPT 가 필요하다는 지시가 있으면 rano-docx·rano-pptx 스킬로 같은 내용을 만든다.
- 작업 폴더에 넣으라는 지시가 있을 때만 리더가 propose_changes 로 올린다.
- 비밀 값(.env, 토큰, 비밀번호)과 개인 정보는 넣지 않는다.
